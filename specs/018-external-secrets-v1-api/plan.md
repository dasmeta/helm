# Implementation Plan: External Secrets v1 API Default

**Branch**: `DMVP-10355-external-secrets-v1` | **Date**: 2026-08-10 | **Spec**: `/specs/018-external-secrets-v1-api/spec.md`  
**Input**: Feature specification from `/specs/018-external-secrets-v1-api/spec.md`

## Summary

Move the External Secrets resources generated by `charts/base` and `charts/namespaces-and-docker-auth` from the deprecated `external-secrets.io/v1beta1` to the stable `external-secrets.io/v1`. `charts/base` already exposes `externalSecretsApiVersion`, so only its default changes. `charts/namespaces-and-docker-auth` hardcodes the version in two cluster-scoped templates, so it gains an equivalent value. Rendered specs are otherwise untouched, making this an apiVersion-only change for consumers.

## Technical Context

**Language/Version**: Helm template DSL, YAML manifests  
**Primary Dependencies**: Helm 3 CLI, External Secrets Operator CRDs (`external-secrets.io/v1`)  
**Storage**: N/A  
**Testing**: `helm lint`, `helm template` with default, override, and example values  
**Target Platform**: Kubernetes clusters running an external secret operator that serves `external-secrets.io/v1`  
**Project Type**: Helm chart repository  
**Performance Goals**: Render behavior unchanged; no new iteration or lookup  
**Constraints**: apiVersion-only change; no rendered spec field may move; per-release override must remain available for clusters on a lagging operator  
**Scale/Scope**: Two charts (`base`, `namespaces-and-docker-auth`), one new example under `examples/namespaces-and-docker-auth/`, and Speckit artifacts under `specs/018-external-secrets-v1-api/`

**Structure Decision**: Keep the two charts independent. `base` renders a namespaced `ExternalSecret` per service; `namespaces-and-docker-auth` renders cluster-scoped resources that affect every matched namespace at once. Sharing a value between them would couple two different blast radii, so each keeps its own.
